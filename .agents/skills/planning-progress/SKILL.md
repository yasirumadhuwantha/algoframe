# Planning and progress

Use the repository's feature inventory and single progress log named by its root instructions. Do not create competing roadmaps or status files for the same work.

- Inspect the relevant implementation, scripts, tests, docs, agent instructions, and Git state. Record unavailable evidence and preserve pending user work.
- Before editing, identify the feature, observable acceptance criteria, scope, baseline, and the next small reviewable step. Prefer a short checklist over a speculative multi-stage plan.
- Record material decisions and their reason, including why new tooling is needed, if any. Keep product facts in project context rather than copying them into reusable skills.
- Record commands actually run, exit/results, failure causes, and verification scope. Separate implementation finished from acceptance verified. Use planned, in progress, verified, or blocked with a specific unresolved condition.
- Update the progress record as evidence arrives. List unfinished work and the next verification needed. Update the workflow summary whenever a rule, skill, or workflow changes.
- Before completion, reconcile the feature inventory, progress record, documentation, and delivered changes. Do not label a feature complete on the strength of a proposed test or an unavailable check.
